## Production cutover and finalize

- production mutation前にcandidate、短命staging evidence、environment parity、Cloud Run foundation、
  controller authorization、Cloudflare/Pages/Access/RunPod control planeをread-backした。
- cutoverは同じcandidateをdeployし、exact-one smoke authorizationだけを開いた。通常UIのsmokeはCloud Run lifecycle、
  3成果物、manifest、正の処理時間、Discord通知、cleanupを成功した。
- finalizeは`smoke-paused`から再開し、production smokeのD1 `provider_handle`とFirestore `executionHandle`を
  完全一致させてから、smoke authorizationを閉じ、有限operational authorizationを適用した。
- operational authorizationは最大5 execution、worst-case合計1,250 JPY、1 executionあたり250 JPY、
  24時間以内の期限に限定した。自動fallbackや無制限authorizationは有効化していない。
- final parityはadmission active、provider `cloud_run_jobs_l4_v1`、Access、secret名、candidate/staging identityを
  再検証し、schema version 2のimmutable production release evidenceを発行した。
